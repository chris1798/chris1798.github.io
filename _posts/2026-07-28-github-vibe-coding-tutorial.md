## 2. GitHub 和 Git 的差別（1:02）

### 什麼是 GitHub？

你可以先簡單把 **GitHub** 理解成**程式碼專用的 Google Drive**：

- 工程師們都會把程式碼上傳到 GitHub
- 讓有權限的人都能夠隨時查看
- 甚至是一起編輯

### 那 Git 是什麼？

**Git 則是幫你在本機端管理程式碼版本的工具**。

兩者關係：
```
GitHub（雲端儲存） = Git（本機管理）的上傳目標
```

### 為什麼需要 Git？

因為 GitHub 主要是用來讓大家協作跟追蹤程式碼進度的，所以**他不收單純的檔案，他只接收已經做好版本紀錄的專案**。

也就是說，在上傳之前，你必須先在自己的電腦裡，幫程式碼建立起這個紀錄系統。

### 沒有 Git 的困擾

如果今天沒有 Git：
- AI 不小心把原本好好的程式給改壞了
- 你根本不知道 AI 剛剛到底動了那些檔案
- 完全不知道該怎麼讓程式恢復到上一個正常的狀態

但有了 Git 就不一樣了，**不管 AI 怎麼亂改，你隨時都有辦法把程式恢復到之前正常的樣子**。

## 3. Commit 與 Push（3:21）

### Commit = 存檔

當你有這種想要存檔的念頭時，對應著 **Git 裡面的 Commit 功能**。

你可以把 **Commit 想像程式在玩遊戲的時候，打大魔王之前你會先手動存檔的那個動作**。

**Commit 最大的價值在於**：
- 幫你的程式碼建立了一個**絕對安全的檢查點**
- 只要你做個 Commit，這份正常的狀態就被**永久封存**了
- 就算 AI 發瘋，把你的程式碼全刪了或是改成亂七八糟，你都可以**瞬間把程式碼還原**回你當初 Commit 的那個完美狀態

> 💡 **重點提醒**：Commit 不是上傳，也不是把東西放到 GitHub 上。Commit 只是單純在你自己的電腦裡面，幫目前的狀態留下一份紀錄而已。

### Push = 上傳到雲端

當你有這種想把電腦裡存好的進度上傳到雲端的念頭時，對應的 Git 動作就叫做 **Push**。

**Commit 跟 Push 完全是兩回事**：
- **Commit** = 在你自己的電腦裡面存檔
- **Push** = 真的把你電腦裡存好的檔案推送到雲端的 GitHub 上

## 4. Clone、Pull 與 Branch（6:11）

### Clone = 複製遠端專案到本地

當你想把 GitHub 上的專案複製到本地電腦時，使用 **Clone**。

### Pull = 從遠端同步最新版本

當别人更新了 GitHub 上的專案，你想同步到你的本地時，使用 **Pull**。

### Branch = 分支（平行開發）

**Branch 允許你在不影響主線開發的情況下，獨立開發新功能**。

這在 Vibe Coding 中特別重要，因為你可以：
- 在主分支上保持穩定的程式碼
- 開一個新的分支來測試新功能
- 測試沒問題後再合併回主分支

---

## 5. Worktree 與 PR 合併（10:42）

### Worktree = 同時開發多個分支

**Worktree 允許你同時在本地操作多個分支**，不用一直切換 branch。

這對 Vibe Coding 特別有用，因為你可能需要：
- 同時修復 bug（在一個分支）
- 開發新功能（在另一個分支）

### PR (Pull Request) = 請求合併

**PR 是請求將你的分支合併到主分支的正式流程**。

PR 的好處：
- 可以預覽變更內容
- 可以請別人審查
- 可以討論並修改
- 合併前可以確保品質

## 6. 改壞怎麼救、總結（15:53）

### 程式被 AI 改壞了怎麼辦？

**別慌！用 Git 隨時還原**：

1. **`git log`** — 查看歷史紀錄
2. **`git revert`** — 還原到某個版本
3. **`git checkout`** — 回到特定的 commit

### 重要觀念總結

| 概念 | 比喻 | 用途 |
|------|------|------|
| **Commit** | 遊戲存檔 | 建立檢查點，方便還原 |
| **Push** | 上傳雲端備份 | 把本地存檔同步到 GitHub |
| **Clone** | 複製他人檔案 | 把遠端專案拉到本地 |
| **Pull** | 同步最新版本 | 從 GitHub 拉取最新變更 |
| **Branch** | 平行世界 | 獨立開發不影響主線 |
| **PR** | 正式審查流程 | 合併前讓他人審查 |
| **Worktree** | 多工處理 | 同時操作多個分支 |

## 給 Vibe Coder 的實戰建議

### ✅ 好習慣

1. **養成 Commit 習慣** — 每完成一個功能就存檔
2. **寫清楚 Commit message** — 讓未來自己能看懂當時做了什麼
3. **定期 Push** — 避免本地檔案遺失
4. **用 .gitignore** — 排除機密檔案（如 API keys）
5. **用 Branch 開發新功能** — 不要直接在主分支改

### ❌ 壞習慣

1. **很久不 Commit** — 萬一出問題損失很大
2. **Commit message 寫「更新」** — 未來完全看不懂
3. **不 Push** — 只在本地有備份
4. **直接在主分支改** — 容易影響穩定版
5. **忽略 .gitignore** — 可能把機密上傳到公開倉庫

## 常見問題 FAQ

### Q: Commit 和 Push 可以一起做嗎？
A: 可以，有些工具會提供 `Commit & Push` 的快捷操作，但本質上還是兩個獨立的動作。

### Q: 如果 AI 把程式改壞了，能不能完全還原？
A: 只要你有做過 Commit，就可以用 `git revert` 或 `git checkout` 回到那個時間點。

### Q: 多個人可以用同一個 GitHub 專案嗎？
A: 可以！這就是 GitHub 的核心功能。透過 Branch 和 PR 的流程，多人可以協作開發。

### Q: 沒有 GitHub 帳號可以用嗎？
A: 可以，GitHub 有免費帳號。其他選擇還有 GitLab、Bitbucket 等。
